# Tronix 解结

一个拖动节点、解开直线线网的小游戏。原生 HTML、CSS、JavaScript，无依赖、无构建步骤，可直接打开 `index.html`，也可通过静态 HTTP 服务访问。

让全部连线不再非法接触即可通关。移动次数记录当前历史和固定关卡最佳成绩。

## 运行

从仓库根目录启动静态服务：

```sh
python -m http.server 8000 --bind 127.0.0.1
```

访问 `http://127.0.0.1:8000/tronix/`。`engine.js` 和 `game.js` 使用传统 `script`，没有 ES modules，因此 `file://` 直接打开也能运行。

## 操作

- 鼠标或单指拖动节点。
- 点选节点，再点棋盘空白处，把节点移到该位置。
- `Tab` 在节点间移动焦点；方向键每次移动 8 个坐标单位，`Shift` 加方向键为 32。
- `Z` 撤销，`R` 重开。
- 多指操作会取消正在进行的拖动并让页面继续处理缩放手势。`touch-action: pinch-zoom` 保留双指缩放；拖动中的节点元素不会被重建。
- 切关、重开、开展每日或随机挑战都会结束当前拖动。撤销记录按一次完成的拖动、一次点选移动或一次键盘移动记一步。

## 判定规则

以下任一情况都算冲突：

- 两条不共享端点的边在内部相交。
- 一条边的端点落在另一条边的内部。
- 两条边共线且重叠长度大于零，即使它们共享一个端点。
- 两个节点重合。
- 一个节点落在与它不相连的边上。
- 节点坐标超出棋盘边界。

两条边只在一个共享端点相接是合法的。两条边沿同一直线向相反方向延伸、仅在共享端点相接，也合法。共线后继续延伸到同一条线段上则判为重叠冲突。

界面实时重算冲突数量，并把相关边和节点标红。冲突数量包含上述各类冲突关系；共享端点不会计入。

## 十二张固定线网

| 关 | 名称 | 节点 | 边 | 结构 |
| --- | --- | --- | --- | --- |
| 1 | 同心方环 | 8 | 12 | 内嵌四边形与四条辐线 |
| 2 | 九宫初网 | 9 | 14 | 3×3 网格加两条对角边 |
| 3 | 双六边形 | 12 | 18 | 内外六边形与六条辐线 |
| 4 | 交错长梯 | 12 | 21 | 两排节点、梯级与单向对角线 |
| 5 | 三重五环 | 15 | 25 | 三层五边形与径向连接 |
| 6 | 方格密网 | 16 | 33 | 4×4 网格三角剖分 |
| 7 | 三角原野 | 18 | 38 | 三至六节点的三角格梯形 |
| 8 | 环中庭院 | 20 | 36 | 双八边形、四节点内环与八条内接边 |
| 9 | 十边之眼 | 21 | 40 | 双层十边形、中心与十向轮辐 |
| 10 | 三角密林 | 21 | 45 | 六至一节点的三角形三角格 |
| 11 | 四六织网 | 24 | 53 | 4×6 网格全单元三角剖分 |
| 12 | 层叠迷宫 | 26 | 42 | 十边形、十边形、六边形三层嵌套 |

每张图在 `engine.js` 的 `LEVELS` 中保存同一组节点、边、起局坐标和一份无交叉直线解坐标。起局坐标由每关固定种子确定性生成，并在载入模块时连同初始冲突数写入 `LEVELS`。固定起局都验证过至少存在一处冲突，因此不会开局即胜利。

节点编号经过确定性重标，与隐藏解的排列顺序无关。手机棋盘采用更高的比例，节点点击区为 44px，并加大初始节点间距。

分级“入门、进阶、困难、专家”、节点数、边数和初始冲突数描述图的结构。人类解谜时间还取决于初始位置和操作方式，这些指标不构成难度排名。

## 每日与随机

每日挑战使用北京时间日期作为种子。`shanghaiDateString()` 按 UTC+8 生成 `YYYY-MM-DD`；`dateSeed()` 把日期哈希为稳定的 32 位种子。同一天重复打开会得到同一张线网。

随机挑战每次点击生成新种子，三局中有两局使用困难、一局使用专家规模。每日与随机图使用凸多边形上的随机三角剖分：先取按圆周顺序排列的节点并加入边界环，再随机加入互不交叉的弦，直到达到目标边数。该构造直接给出无交叉见证，随后重标节点，生成随机起局坐标并校验冲突。

每日与随机挑战不写入固定关卡星星或最佳次数，也不改变十二星进度。

## 记录

固定关卡记录保存在 `localStorage` 的独立键：

```text
yaozi.tronix.progress.v1
```

数据结构：

```js
{
  version: 1,
  stars: [false, false, ...],   // 12 项
  best: [null, null, ...]       // 12 项，单位为本局移动次数
}
```

首次解开固定关卡时点亮星星，并记录当次移动次数；之后只在次数更少时更新最佳。重开、撤销、更换关卡、每日和随机都不会清除已保存记录。存储不可用时游戏仍可操作，记录只保留在当前页面。

主题读取 `yaozi.home.theme`，手动切换时写回同一个键；没有手动偏好时跟随系统主题。

## 引擎接口

`engine.js` 是 UMD 纯函数模块。浏览器中暴露 `window.TronixEngine`，Node 中通过 `module.exports` 使用。主要导出：

| 接口 | 说明 |
| --- | --- |
| `LEVELS` | 12 个冻结的固定关卡，含 `nodes`、`edges`、`start`、`solution`、`meta` |
| `BOUNDS` | 棋盘坐标边界 `{minX, maxX, minY, maxY}`，画布为 1000×750 |
| `pointOnSegment(point, a, b, tolerance?)` | 点是否落在闭线段上 |
| `segmentRelation(a, b, c, d, tolerance?)` | 返回 `none`、`shared-endpoint`、`cross`、`touch` 或 `overlap` |
| `segmentsConflict(a, b, c, d)` | 几何线段冲突判断；仅共享端点不算冲突 |
| `detectConflicts(points, edges, { bounds? })` | 返回 `valid`、`count`、`conflicts`、`edgeFlags`、`nodeFlags`、`outOfBounds` |
| `validateSolution(points, edges, { bounds? })` | `detectConflicts` 的语义化别名 |
| `generate(seed, difficulty)` | 生成确定性线网；难度为 `easy`、`medium`、`hard` 或 `expert` |
| `shanghaiDateString(date?)` | UTC+8 日期字符串 |
| `dateSeed(dateString?)` | 日期对应的稳定 32 位种子 |
| `dailySeedForDate(date?)` | 直接取某个时刻的每日种子 |
| `randomStartLayout`, `scrambleLayout` | 生成确定性随机起局坐标 |
| `clampPoint`, `labelsFor`, `clonePoints`, `cloneEdges` | 坐标与数据辅助函数 |

固定关卡与随机生成结果都带有 `meta.witnessValid` 和 `meta.initialConflicts`。

## 浏览器接口

`window.TronixGame` 提供：

- `ready()`：返回在初始化完成后兑现的 Promise。
- `loadLevel(index)`：载入 0 到 11 的固定关卡，返回是否成功。内部 UI 与公开接口使用同一套 0 基编号。
- `snapshot()`：返回可结构化克隆的当前状态，包括模式、关卡信息、图、坐标、冲突、选中节点、拖动状态、移动历史长度、记录和存储可用性。

稳定 DOM 接口：

- 节点按钮：`#node-0` 到 `#node-25`，带有 `data-index="<0 基索引>"`。
- 关卡按钮：`#level-0` 到 `#level-11`，带有 `data-level="<0 基索引>"`。
- 主要控件：`#undo`、`#restart`、`#next`、`#daily`、`#random`、`#theme`。
- 棋盘元素：`#board`、`#board-surface`、`#links`、`#node-layer`。

`#next` 只在固定关卡解开且还有下一关时显示。每日与随机不会显示下一关入口。

## 验证

```sh
node tronix/verify.cjs
```

`verify.cjs` 使用 Node 标准库，不依赖浏览器或安装包，检查：

- 正常交叉、共享端点、共线重叠、端点贴合与点在线段上的分类。
- 节点重合、节点落在无关边上、边界检查。
- 十二个固定解在边界内合法，且每关起局都有冲突。
- 固定关卡的边集互不重复，前两关保持短入门规模。
- 随机线网在相同种子下图、起局和解完全一致。
- 多组随机图带合法见证、起局冲突和正确的元数据。
- 北京时间跨日边界与日期种子的稳定性。
- 无效难度名称会报错。

## 实现约定

- 棋盘画布使用 SVG 画边，节点使用绝对定位的 HTML 按钮。节点坐标保存在 1000×750 坐标系中，界面按百分比定位，因此窗口尺寸变化后节点与边仍然对齐。
- 拖动只在完成时写入一次撤销记录。拖动中的 `pointermove` 更新坐标和冲突显示，不重建节点按钮。
- 节点被限制在 `BOUNDS` 内。多指操作、`pointercancel` 和系统手势会回退未完成的拖动。
- 保存键与主题键分开；每日、随机和重开不会改动固定星记录。
