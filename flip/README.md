# 翻转全亮

按下一格，它会翻转自己，以及格子里那张 3×3 小图标出的邻格。全部方格亮起即通关。

每格的作用范围都不一样：有的只带上上下下左右，有的还带上斜角。小图就是这一格的作用图，界面里逐格显示，不需要靠位置去猜。

从仓库根目录启动静态服务后访问 `/flip/`，也可以直接打开 `index.html` 离线游玩。页面只用原生 JavaScript，没有构建步骤和外部依赖。

## 操作

- 点击方格翻转。已亮的格子按下去会熄灭。
- 方向键移动焦点，Enter 或空格按下。
- Z 撤销，R 重开，H 提示当前局面最少还需要几步，并高亮其中一步。
- 动画可选流畅、快速或关闭，默认跟随系统的“减少动态效果”设置。

## 预算：每关的最优步数

每关的**预算**是该题的最少按键次数，由程序精确算出，不是某条打乱序列的长度。按下次数达到预算而棋盘尚未全亮，本局失败，可以撤销或重开。撤销与重开都不清除已得的星星。

同一格两次翻转互相抵消，按下顺序也不影响结果，所以一局真正决定的东西只是按了哪些格。这也是预算可以被精确计算的原因。

## 十二关

前四关是 3×3，中间三关 4×4，最后一组五关 5×5，预算从 3 步逐步升到 13 步。邻域风格在前四关之后由十字扩展到混合作用图。

其中五关的矩阵是奇异的，同一盘棋有多个解（最多的两关分别有 16 个和 4 个解）。奇异不代表更容易：解的数量由零空间维数决定，最少步数仍要另外算出来。

每日与随机题目不计入十二星。每日题按北京时间日期确定种子，当天所有用户得到同一盘棋，与随机按钮和本地记录无关。

## 精确求解

`engine.js` 是 UMD 纯函数模块，浏览器中为 `FlipEngine`，Node 中可 `require`。棋盘表示为 `{w, h, cells, masks}`：`cells[i]` 是 0/1，`masks[i]` 是 9 位掩码，第 `b` 位对应相对偏移 `(dx, dy) = (b % 3 − 1, ⌊b / 3⌋ − 1)`，中心位恒为 1。

`apply(state, {type:'flip', index})` 返回翻转后的新状态和被翻转的格子。`replay(state, solution)` 回放一条按键序列并检查是否全亮。`solve(state)` 返回 `{solvable, optimal, solution, rank, nullity, solutionCount, exact}`。

求解过程分三步：

1. 把“按下第 j 格会动到哪些格”写成矩阵 A 的列，“哪些格还需要翻转”写成向量 b，得到模 2 方程 A x = b。
2. 高斯消元判断是否有解，给出特解 x0，并得到零空间维数 d；全部解是 x0 + ker A，共 2 的 d 次方个。
3. 枚举零空间的全部向量，取按格数最少的一个，其汉明重量就是最优步数。固定关的 d 限制在 4 以内，最多枚举 16 个向量。

高斯消元本身只给可行解，按格数不一定最少；最少步数来自第 3 步的枚举。`exact` 表示枚举是否在维数上限内完成。

生成器反向使用同一套代数：先随机生成每格的作用范围，再挑一组按键方案 x*，用 b = A x* 反推初始棋盘。题目在出题时已经有解，随后求出精确最优值，并保存这条最优按键序列作为证书。候选的作用范围只使用本格邻域内的位置，棋盘角落的掩码不会越界。

每日与随机题目的构造是多项式时间的，不跑搜索，因此不需要 Worker：生成一次只做几十次小矩阵消元，同步执行不会阻塞界面。生成过程中切换关卡或再次点击会递增代数编号，过期结果直接丢弃。

## 存储

- 通关与最佳成绩：`yaozi.flip.progress.v1`
- 动画速度：`yaozi.flip.motion`
- 主题与语言沿用 `yaozi.home.theme` 与 `yaozi.home.language`

存储不可用时仍可游玩，星星在本次打开期间保留。

## 验证

从仓库根目录运行：

```sh
node flip/verify.cjs
node flip/verify.cjs --full
```

脚本独立重写了一套模型，而不是复用引擎内部函数：

- 用广度优先搜索计算 3×3 和 4×4 的完整距离表，再抽样对齐 `solve` 的最优值；`--full` 逐一核对完整状态空间。
- 用 BigInt 行向量、朴素子集枚举的第二套精确求解器，核对十二关与生成题的 `optimal`、`nullity`、解数量。
- 回放十二关与多个随机种子的证书，检查每步合法、终局全亮、按格数等于预算。
- 手工构造十字掩码与 2×2 奇异棋盘，检查位序约定、两次按下抵消、顺序无关、非法棋盘被拒。
- 检查每日种子确定性与北京时间日期边界。

## 页面接口

浏览器对象 `window.FlipGame`：

- `snapshot()` 返回深拷贝，含 `puzzle`（题目与证书）、`state`、`moves`、`won`、`levelIndex`（非固定关为 `null`）、`mode`、`stars`（12 个布尔值），以及 `status`、`budget`、`solution`、`nullity`、`solutionCount`、`dailyDate`、`generationPath` 等。
- `loadLevel(index)` 载入 0–11 号固定关卡，成功返回 `true`。
- `ready()` 在没有生成任务、没有进行中的动画时返回 `true`。
- `playSolution()` 用本题证书逐步按下并返回次数；也可按 `snapshot().solution` 自行点击方格回放。
- `hint()` 返回当前局面剩余的最少步数。
- `setMotion(ms)` 只改本次页面内的动画时长（`0` 关闭），不写入存储；自动化检查里用它让 `ready()` 立即为真。

稳定 DOM：`#board`、`#undo`、`#restart`、`#daily`、`#random`、`#next`、`#language-toggle`、`#theme`、`[data-level="0"]`–`[data-level="11"]`。棋盘格子是 `#board` 内的按钮，带 `id="cell-N"` 与 `data-index="N"`，点按即可翻转。另有 `#hint`（提示）、`#cancel`（取消生成）、`#motion`（动画速度）、`#message-title` 与 `#message-text`（状态文字）。
